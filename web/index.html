Change the deployment size

Single node → two nodes

Keep the existing database and cluster ID. Configure a witness, peer connection and unique node IDs. Restart this node with mode = "dual". Initialize the new standby without --bootstrap; it receives a snapshot automatically. Confirm matching terms and sequences before relying on failover.

Two nodes → single node

Choose the current primary and confirm replication is caught up. Stop both mail services. Fence every other mail node: disable its service and prevent it from reconnecting or restarting as a writer. If a peer is lost, choose the surviving database and review the potential unreplicated tail.

Set the retained node to mode = "single", role = "primary", and remove its witness section. On that stopped node, run:

workglen demote-single /etc/workglen/node.toml --peer-fenced

This creates a backup and explicitly changes the database mode. Then start the retained node. The flag asserts that you have fenced the other nodes; Workglen Mail cannot power them off for you. A former peer must be reintroduced as an empty standby, never started with its old writable configuration.
