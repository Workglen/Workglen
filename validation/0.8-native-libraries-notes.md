# Validation notes — typed data/JSON and charsets

The final successful portable logs are in 0.8-native-libraries-checks.
Earlier Serde-only full validation passed 303 tests and the same 217 loopback
assertions before adding native charsets; the final tree passes 305 tests.
Four optional PostgreSQL fixtures remain explicitly ignored. No live provider,
CA, host installation, mailbox or GitLab repository was changed.

Issues found and resolved during implementation:
- Actual-record comparisons caught Webmail unit-command handling of unused
  object fields and trailing sequence elements; the existing behavior is kept.
- TOML snapshots caught its distinct ordinary tuple versus tuple-variant length
  behavior; both now match, and the format boundary has a regression test.
- A synthetic PostgreSQL refusal peer attempted a ReadyForQuery write after
  the client had correctly disconnected. The peer now sends only the relevant
  authentication response; the refusal assertion remains.
- The new standalone harness needed the existing signed-JSON vector file, which
  is now shipped; new-module lint failures were corrected before passing.
- The initial charset corpus caught a BOM-selected UTF-16 odd-byte difference.
  The native standard decoder now preserves the former replacement/error rule;
  existing explicit MIME UTF-16 aliases retain their prior handling. Expanded
  BOM/surrogate cases are in the frozen 2,883,056-case corpus.
- JSON's 414 typed-f64 rounding and two private-marker differences are intentional
  corrections, independently checked and permanently recorded. They are not
  counted as exact matches. No application record field is f64/f32.

Final changes after the full combined run were documentation, provenance and
validation packaging, plus renaming a stale fs2 description in the compatibility
script. Its six checks were rerun successfully under the accurate description.
Pratique patch pre/post hashes were regenerated for comment clarification and
all three patches were checked again against the pinned upstream source.

The retired implementations exist only in isolated optional oracle harnesses.
Their frozen locks are development evidence, not runtime dependencies.
