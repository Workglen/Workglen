# Tokio-removal validation notes

Executed on Linux x86-64 with Rust/Cargo 1.99.1; no live services or host install.

An early workspace run hit stale Rust artifact metadata (E0460/E0463). Clearing
only the generated Cargo target cache fixed it; no protocol code was changed
for that failure. A standalone Clippy command initially selected upstream
Pratique modules as well as the new module. The shipped harness uses an explicit
package selection and --no-deps, while compiling byte-identical new socket
source into the selected package. This checks new code without claiming to
resolve pre-existing upstream lints. Both early logs are retained here.

The first clean full run passed 241 Rust tests, release Clippy/build and 54
outbound checks, then timed out during local cluster startup after four mail
checks. Its temporary fixture was automatically deleted, so its root cause
cannot be established from that run. The runner now retains failed synthetic
fixtures for diagnosis. The separate fresh mail run passed all 119 checks
without a production-code change, and Webmail/installer passed 34/10 checks.
The final full sequence passed all 11 runner stages, including all 241 Rust
tests and 217 integration assertions. Its unmodified logs and machine-readable
results are saved in 0.8-native-tokio-portable/.

Four optional PostgreSQL fixture tests remain ignored in the ordinary runner.
Native macOS compilation/runtime, production load and live providers were not
validated. These tests are not an independent security or cryptographic audit.
