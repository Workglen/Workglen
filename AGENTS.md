# Workglen implementation instructions

Read security/DEPENDENCY-POLICY.md for any Mail Security change. Preserve the native single-executable deployment, embedded storage, first-party inspection/decompression, mandatory incomplete-scan quarantine, independent mailbox/domain/instance permissions, rule lifecycle and append-only audit evidence. Do not add a mandatory security runtime/service or fetch executable content during scanning.

Minimize third-party crates throughout the suite. Reuse std or existing Pratique/Lazaret code when behavior is equivalent, disable unused features, and inspect the complete transitive graph before changing Cargo.toml or Cargo.lock. Do not hide third-party code by vendoring it or weaken security/protocol behavior to lower counts. The direct and transitive allowlists in security/dependency-policy.json require an explicit, documented review for changes. See DEPENDENCIES.md.

Keep tests synthetic and local. Validate security changes with offline locked Rust tests, Clippy, and relevant loopback/browser fixtures. Do not send real mail or remove real mailbox content during development. Never claim detection efficacy or live-provider validation from synthetic tests.

Development installations now exist on a Mac Admin host and a Lightsail gateway. Preserve installed configurations, keys and current data. Target fresh installs and reopening the current schema; do not add Workglen-to-Workglen importers, upgrade conversions or old-format compatibility without a real deployment requirement. Preserve backup/restore, replication, deployment-mode safety, audit history and external-system data exchange. Xero, QuickBooks and other accounting-platform import/export remain product requirements; distinguish implemented adapters from backlog items.

Mail Security storage encryption is mandatory. Preserve supplied/generated key support, owner-only keys outside the data directory, whole-database ciphertext, crash-safe sync/compaction and fail-closed authentication. Never generate a replacement key at startup, silently open plaintext data, expose keys in APIs/logs or claim other modules are encrypted without integrating and testing their storage/backup paths. Read security/ENCRYPTED-STORAGE.md before changing this boundary.

TLS certificate lifecycle is shared across listeners through the native ACME manager. Keep offline commands offline, private ACME state and keys protected, retries bounded and CA trust verification enabled. Use only simulated local CAs in tests; do not issue public certificates during development. See TLS-CERTIFICATES.md.

The local Admin process must not open Mail/SMTP/IMAP/Webmail/replication listeners. Preserve its loopback binding and optional local PostgreSQL connection. Accounting defaults to verified TLS; explicit local transport must reject remote/DNS/multi-host endpoints and hostaddr overrides. Never transfer local database credentials in a gateway pairing bundle. Installer tests must use synthetic local fixtures and staging; do not modify live system accounts, services or firewalls.

Do not reintroduce OpenSSL (including transitive crates, system libraries, build probes or setup subprocesses). Use Pratique and retain cryptographic known-answer, independent interoperability, certificate refusal, channel-binding and encrypted-store recovery checks. RSA provisioning uses the first-party bounded generator, never online request data.

The user-authorized source build installs missing supported system prerequisites, missing Rust/Cargo from the official Rust distribution, and locked Cargo dependencies. The installer must use sudo only for fixed OS package-install operations and must refuse to run Rust setup, Cargo or build scripts as root on the user's host. Reuse installed tools, preserve existing repositories, and do not request a full system upgrade. On macOS, Apple's own tools installer may require desktop interaction. Keep source-build tooling separate from the deployed runtime. `check` and `build --offline` must never install or download anything. Test bootstrap paths only with isolated fake tools; do not run real package managers, sudo, Apple setup or toolchain installation during regression tests. Direct offline compilation of an isolated validation copy may use the executor's only mapped UID; this must not bypass the installer's root refusal or be represented as user-host validation.
