# Native mail authentication — DEPS-13

`mail-auth` 0.13.3 is fully removed from Cargo.toml, Cargo.lock and vendor/.
The graph falls from 96 to **79 external package versions** at this checkpoint:
16 registry packages and the attributed third-party path package disappear.
No registry version is added or changed; retained checksums are unchanged.
The next IDNA checkpoint is cumulative; see DEPENDENCY-CATALOG.md for the latest count.

`src/auth.rs` now selects first-party SPF, DKIM/ATPS and DMARC. Existing timeout,
temporary failure, rejection and quarantine policy remains at the same boundary.
Submission From matching uses the retained MIME/address parser. DKIM signing and
key provisioning continue to use Pratique and the existing protected key files.

## Preserved protocol scope

- SPF mechanisms, qualifiers, include/redirect recursion, macros and explanations;
  shared ten-term/two-void budgets, bounded MX/PTR processing and temporary errors.
- DKIM simple/relaxed canonicalization, streaming body hashes, repeated headers,
  body-length/expiry checks, RSA-SHA256 and legacy RSA-SHA1 verification, strict
  Ed25519, key restrictions, quoted-printable identity and ATPS authorization.
  RSA verification remains bounded to 1024–8192 bits; provisioning stays 2048–4096.
- DMARC RFC 9989 tree discovery, organizational alignment, strict/relaxed modes,
  psd/sp/np/testing policies and duplicate/invalid-record handling.
- DKIM2 signing/verification, real/imaginary hops, envelope custody, multiple
  keys, chained message instances, signed flags, feedback metadata and signed
  DSNs (full returned message or headers only). JSON reconstruction recipes keep
  the deployed wire format, bounded diff and lossless fallback. Processing caps
  are 50 chain entries, 64 KiB headers, 64 MiB messages and 256 MiB reconstruction
  work; excessive work fails rather than silently passing.
- ARC verification/sealing remains available with `--features arc`, including
  newest-message verification, complete seals, contiguous instances and cv rules.

DKIM2 preserves the draft wire format deployed by the prior mail-auth 0.13.3
integration; this is **not** a claim of implementing every subsequent draft.
ARC and DKIM2 retain library APIs; no new automatic forwarding policy is enabled.
Aggregate report delivery/compression was not enabled in Workglen and is not
introduced here. This replacement implements Workglen's protocol scope, not the
entire public SDK of the removed product.

Malformed SPF CIDRs and unknown mechanisms now produce PermError instead of
the former engine's permissive result. Duplicate DMARC records are discarded
at that tree node. These are deliberate standards-based invalid-input changes.

## Independent evidence and reproduction

`tests/mailauth_crypto.rs` and `tests/mailauth_dkim.rs` retain independent Python
RSA/Ed25519 signatures, all canonicalizations, weak/revoked/malformed key refusal,
strict small-order checks and known hash answers. `tools/native-auth-fixtures.py`
adds 17 deterministic independent extension/key-policy cases, including ATPS
none/SHA-1/SHA-256 and DNS timeout handling. All keys are public synthetic fixtures.

`tests/native_protocols.rs` verifies checked-in DKIM2/ARC messages generated by
the former engine. In the reverse direction, that engine successfully verified
the native revised two-hop DKIM2 message and two-hop ARC chain. The recorded SPF
corpus has 48 old-engine cases. Closed-DNS tests cover mechanisms, macro expansion,
budget exhaustion, policy lookup, signed restrictions and DSNs. Recipe tests
retain exhaustive short sequences, an independent LCS oracle, long inputs,
Unicode/binary handling, malformed indices and signed reconstruction.

`tools/mailauth-protocol-oracle.rs` is a development harness, not application
source or a dependency. To reproduce the old-engine side, extract the previous
source version 29 into a separate directory, copy the harness there, add it as a
temporary Cargo bin and enable that copy's `mail-auth/arc` feature. Running with
no arguments emits the protocol corpus; `--spf` emits the SPF corpus. Set
`WORKGLEN_EXPORT_PROTOCOL_FIXTURES=/absolute/output.json` when running the native
protocol test and pass that output path to the old harness for reverse checks.
Use prepared caches and `--offline --locked`; never add the old package here.

Ordinary checks: `cargo test --offline --locked --workspace --all-features`,
warnings-denied Clippy in a separate target directory, release build, and the
existing outbound/mail loopback scripts. Evidence is in `validation/0.8-native-mailauth-*`.
Four optional PostgreSQL tests require an explicit fixture and remain skipped.
These checks are synthetic and do not assert real-provider certification.

## Source and deployment

The protocol implementation is Workglen source. The existing Workglen-authored
Base64 adapter and bounded diff move out of the former vendor tree; the upstream
implementation is not copied or relabeled. Historical attribution/evidence stays
in the preceding archives. MIME `full_encoding` and `base64_slice` are now explicit
direct mail-parser features, preserving the former unified feature selection.

The executable, configuration, keys, data schema and deployment boundaries are
unchanged. Rebuild from a fresh extraction and preserve installed configuration,
keys and data. No service is deployed and no real mail is sent during validation.
